## D4 Engine and replay (from the symbols research, verified)
- Prices as integer points (point = 10^-digits), lots as integer steps, money as integer cents (BigInt fallback). Rounding = Postgres ROUND(numeric,2) (ties away from zero); never toFixed/Math.round on floats for stored values; -0 -> 0. Send DB values as decimal strings.
- Fills on BID data: open LONG at ask = bid close + spread points; open SHORT at bid close; close LONG at bid; close SHORT at ask. Entry time = last revealed 1m bar open + 60 s. TP/SL checks start on the next 1m bar.
- Triggers per 1m bar: LONG on BID (SL if low <= SL, TP if high >= TP); SHORT on ASK (SL if high + s >= SL; TP if low + s <= TP). Gap at open beyond SL fills at the open (slippage); beyond TP fills at TP (conservative).
- Chart candles of any timeframe are resolved through their 1m bars ("bar magnifier"), which satisfies R24's smaller-timeframe rule. Residual case (TP and SL inside the SAME 1m bar): 1m is the smallest archived timeframe, so the rule is SL first (worst case) and the trade is flagged exit_ambiguous. Owner decision (alternative: open-proximity/OHLC path).
- P&L USD: gross = dir x (exit - entry) x lot x contractSize; toUsd 'quote' x1 (USDT = USD); 'base' (USDJPY) / exit price (mark price for floating). Commission = round-turn per lot, booked at close; floating net = gross(mark) - full commission. Balance = starting_balance + sum(net of closed). Equity = balance + floating.
- rr_ratio = ROUND(|tp - entry| / |entry - sl|, 2) on the real fill entry and initial SL/TP, NULL if either missing or risk = 0 (identical to trg_calc_pnl, so its overwrite is a no-op).
- Aggregation: M1, M5, M15, M30, H1, H4, D1. M1-H1 on the UTC grid; H4/D1 anchored to the symbol day start (17:00 New York for FX/gold, 00:00 UTC for crypto). Only existing 1m bars are aggregated; no synthetic bars. The in-progress candle = aggregate of 1m bars <= cursor.
- Cursor = index into the time-ordered 1m array; replay_time = open time of the last revealed 1m bar + 60 s. Data after the cursor is never given to the chart (future never visible). Stepping moves over existing 1m bars, so closed sessions are skipped. "Step" = complete the current bar / advance one bar of the chart timeframe; "play" advances 1m bars at the selected speed so higher-timeframe candles visibly form. Go-to-date = nextOpen(t) then first bar >= t'.
- Persist replay_time debounced (e.g. every 5 s while playing, on pause, on trade actions, on leave). PAGE.onLeave clears every timer/RAF/observer, removes the chart, closes viewers.
- Display: series times stay true UTC; labels in the user's timezone via LWC localization.timeFormatter / tickMarkFormatter (not pseudo-UTC shifting, which breaks on DST fall-back for 24/7 crypto). priceFormat precision = digits, minMove = point.

## D7 Data archive (R36-R45, R47) — details finalized from the dukascopy/binance/storage tracks
- Sources: Dukascopy BID 1m day files (bi5 = LZMA "alone"; record [offsetSec, O, C, L, H, vol float32], big-endian, 24 bytes) for EURUSD/GBPUSD/USDJPY/XAUUSD; Binance spot monthly 1m zip + CHECKSUM for complete months and daily zips for the current month (open_time ms until 2024, µs from 2025). 2020-01 to today.
- LZMA: a small vendored pure-JS LZMA-alone decoder ported from the public-domain LZMA SDK (no npm). Verified against xz in tests with a synthetic fixture.
- ZIP: minimal reader on zlib.inflateRawSync.
- Month file: gzip JSON {v, symbol, month, tf:'1m', digits, source, rows:[[t,o,h,l,c],...]} with t = UTC epoch seconds (bar open), prices rounded to the symbol digits. manifest.json: per symbol/month bars, first/last time, sha256, partial flag, coverage, quality summary, updatedAt.
- Importer modes: backfill (missing months only, resumable) and daily (new days only; merges them into the current month file, updates the manifest last). Failures exit non-zero with a clear message; the newest day not yet published (Binance lag) is a warning for up to 2 days, then a failure (owner decision).
- GitHub Actions (private repo): schedule 02:00 UTC + workflow_dispatch; concurrency group; timeout 30 min (dispatch backfill longer); Node 22 via pinned actions; no npm install; secrets SUPABASE_SERVICE_ROLE_KEY, var SUPABASE_URL; quality report artifact 14 days.
- Browser: download via sb.storage.from('candles').download(path) with the user's session; DecompressionStream('gzip'); in-memory LRU of a few months; persistent cache for past months (Cache Storage or IndexedDB, try/catch); prefetch the next month near its end and previous months for warm-up history. CandleSource abstraction (ArchiveSource now; a LiveSource later for R46). Chart shows a source label "Arşiv · Dukascopy|Binance" (owner decision to show it now).

## D13 Corrections from the cross-design review (inputs/w3/review_design.json) — override earlier sections
- Go-to-date vs "future never visible" (R23): once an account has trades, replay_time is MONOTONIC. Backward jumps are allowed only on accounts without trades, or through an explicit, confirmed "reset account" that deletes its trades (and its journal mirrors). Forward go-to-date is disabled while positions are open (message to the user). As a second layer, markers, price lines, history rows and realized P&L only include trades whose times are <= the cursor.
- Cursor = a TIMESTAMP (t of the last revealed 1m bar), not an array index; indices are found by binary search inside month chunks, so prepending warm-up months never shifts the cursor.
- bt-candles.js exposes only cursor-bounded functions (aggregateUpTo(cols, tCursor, tf) and an incremental update); series.setData never receives a bar that starts after the cursor's bucket; precomputed higher-timeframe bars may be cached only for buckets that end at or before the cursor. Property test for random cursors.
- H4 and D1 buckets use the DST-aware WwBtSymbols.dayAnchor (17:00 New York for FX/gold, 00:00 UTC for crypto); never a constant offset. Tests across 2026-03-08 and 2026-11-01.
- Schema (Migration 02): stop_loss / take_profit are the CURRENT levels (editable while open); add immutable initial_stop_loss / initial_take_profit set at open; rr_ratio is computed from the initial levels at open; the journal mapping sends the initial levels as trades.stop_loss / take_profit (so trg_calc_pnl's rr recompute is a no-op). Account spread_pips / commission_per_lot cannot be edited while the account has open positions.
- XAUUSD: digits 2, pipSize 0.1, decided once in bt-symbols.js; importers convert source prices with integer arithmetic (half-up) to the config digits; the loader rejects files whose digits differ from the config.
- bt-symbols.js also carries an explicit, commented pipValue per symbol ({ perLot, ccy }), checked by validate() against pipSize x contractSize.
- Crypto spread is relative: the config marks crypto with spreadUnit 'bps' (ask = bid x (1 + bps/10000) rounded to the point grid); FX/gold use pips. The account's spread_pips column holds the value in the symbol's unit and the UI labels it accordingly. (Crypto is disabled anyway until the licence decision.)
- Archive manifest: one index.json PER SYMBOL (and per source prefix), not one global manifest; each month entry carries a per-UTC-day ledger {status ok|closed|missing|failed, source, sha256}; a month is final only when every day is ok or closed, otherwise 'incomplete' and retried on every run. Every importer run takes a per-symbol lock object (created without x-upsert, stale after 2 hours) so the scheduled job and a manual run never write concurrently.
- Browser cache: IndexedDB only (public/sw.js deletes every other Cache Storage cache on activate). Clear it on EVERY sign-out path: register sb.auth.onAuthStateChange(SIGNED_OUT -> delete the 'ww-candles' database) in public/config.js, plus a stored owner user id that wipes the cache on mismatch.
- Storage reads that fail with NoSuchBucket/NoSuchKey/404 may be auth failures: check the session, refresh once and retry before showing "not found".
- Warm-up history: one historyMonths(tf, symbol) function (target ~200 bars, cap 6 months), used by loader and tests.
- Migration 03 aborts if a 'candles' bucket already exists with objects, public = true or different limits (unless an explicit override), adds read-only post-checks of storage.buckets policies, and Migration 07 (open to users) also excludes anonymous sign-ins (coalesce((auth.jwt()->>'is_anonymous')::boolean, false) = false).
- Importer secret: prefer a dedicated new-style Supabase secret key for the importer (same service-role level, independently rotatable) stored in GitHub Secrets; workflow permissions contents: read; actions pinned by SHA; no pull_request triggers.
- Importer code uses only Date.UTC/getUTC*; its tests run under TZ=Asia/Istanbul and TZ=America/New_York.
- Pending orders stay out of v1 (R24 lists market orders only).
